# StreamHub — учебная копия YouTube

StreamHub — видеохостинг, реализованный по приложенному тестовому заданию. Это самостоятельный проект на **Python + FastAPI + PostgreSQL** с простым фронтендом, RustFS (S3-compatible object storage), Redis и Celery для фоновой обработки видео.

## Объектное хранилище

В Docker Compose используется **RustFS** — S3-совместимое объектное хранилище. Оно заменяет недоступный для анонимной загрузки официальный образ MinIO. Для совместимости с уже существующими настройками Compose-сервис по-прежнему называется `minio`, поэтому `S3_ENDPOINT_URL=http://minio:9000` менять не нужно. Консоль хранилища доступна на `http://localhost:9001`; ключ и секрет берутся из `S3_ACCESS_KEY` и `S3_SECRET_KEY` в `.env`.

## Возможности

- Главная лента в стиле YouTube: горизонтальные тематические фильтры, сортировка по новизне и популярности, поиск по названию и описанию.
- Боковая библиотека: история просмотров, плейлисты, «Смотреть позже», понравившиеся, собственные видео, загрузки и подписки.
- История, «Смотреть позже» и список инициированных загрузок хранятся в браузере; лайки, плейлисты и подписки — в базе данных.
- Страница просмотра: HTML5-плеер, перемотка через HTTP Range, просмотры, лайки, комментарии и жалобы.
- Каналы авторов, подписки, плейлисты с созданием пользовательских подборок.
- Регистрация, вход и выход; роли `user`, `moderator`, `admin`.
- Загрузка MP4/MOV/MKV/WEBM с индикатором прогресса, метаданными и лимитом размера.
- Фоновая обработка через Celery + FFmpeg: проверка файла, MP4 H.264/AAC, JPEG-превью, длительность и статус обработки.
- Девять демонстрационных видео по темам науки, природы, технологий, истории и космоса. Видеофайлы и превью создаются локально при первом заполнении базы.
- Приватные видео. По умолчанию их видит только владелец; владелец может выдать доступ зарегистрированным пользователям по email и отозвать его.
- Очередь жалоб, закрытие жалоб и скрытие/восстановление видео для модераторов и администраторов.
- Swagger UI: `/docs`; OpenAPI: `/openapi.json`.

## Быстрый запуск

Для локальной проверки достаточно Docker Engine и Compose plugin. `compose.yaml` содержит значения по умолчанию и не требует наличия файла `.env`; можно выполнить:

```bash
docker compose up -d --build
```

Для развёртывания на Ubuntu 22.04/24.04 рекомендуется использовать `deploy.sh`: скрипт проверяет Docker, при необходимости устанавливает Docker Engine и Compose plugin через официальный bootstrap-скрипт, создаёт `.env` со случайными секретами и запускает контейнеры.

```bash
unzip streamhub.zip
cd youtube-copy
chmod +x deploy.sh
./deploy.sh
```

`deploy.sh` создаёт `.env` с новыми секретами при первом запуске и запускает PostgreSQL, Redis, RustFS, API, одноразовый сервис `seed` и worker. Миграции выполняются до запуска API. Генерация демонстрационных видео вынесена в отдельный `seed` после готовности API: долгая работа FFmpeg и загрузка файлов в RustFS больше не задерживают запуск Uvicorn и healthcheck. Повторный запуск безопасен: уже существующие demo-пользователи и видео не дублируются. Если база была создана предыдущей версией проекта, seed добавит недостающие демо-видео, не удаляя существующие записи.

После запуска:

| Сервис | Адрес |
|---|---|
| Приложение | <http://localhost:8000> |
| Swagger | <http://localhost:8000/docs> |
| ReDoc | <http://localhost:8000/redoc> |
| Healthcheck | <http://localhost:8000/health> |
| Object storage console (RustFS) | <http://localhost:9001> (учётные данные `S3_ACCESS_KEY` / `S3_SECRET_KEY` из `.env`) |

## Управление

```bash
docker compose ps                 # состояние контейнеров
docker compose logs -f            # логи всех сервисов
docker compose logs -f api worker  # API и обработка видео
docker compose logs -f seed        # создание демонстрационных видео при первом запуске
docker compose down               # остановить сервисы, сохранить данные
docker compose down -v            # УДАЛИТЬ контейнеры и все volumes с данными
```

Для локального тестирования кода без Docker (нужны PostgreSQL, Redis, RustFS и FFmpeg):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt  # включает Pillow для генерации демо-превью
cp .env.example .env
# Для локального запуска поменяйте хосты db/minio/redis (в Compose сервис `minio` запускает RustFS) на localhost в .env.
alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload
```

В отдельном терминале запустите worker:

```bash
celery -A app.tasks.celery_app.celery_app worker --loglevel=INFO
```

## Архитектура

```text
Browser
  │ same-origin HTTP / HTML / JSON / byte-range stream
  ▼
FastAPI ─────────────── PostgreSQL
  │  │                     (users, videos, ACL, comments,
  │  │                      likes, subscriptions, playlists, reports)
  │  └────────────────── Redis (Celery broker/result backend)
  │                            │
  │                            ▼
  │                         Celery worker ── FFmpeg / ffprobe
  │                            │
  └────────────────────────────┴──────────── RustFS (S3-compatible)
                               originals / processed MP4 / thumbnails
```

API не отдаёт браузеру адрес объектного хранилища. Поток видео и превью проксируются через FastAPI с проверкой доступа. Для просмотра поддерживаются `Range` / `206 Partial Content`, что позволяет браузерному видеоплееру перематывать ролик. Оригинал и производные файлы хранятся в объектном хранилище, бинарные данные видео не попадают в PostgreSQL.

## Структура проекта

- `app/api/` — HTTP-маршруты: авторизация, видео, каналы и плейлисты, модерация;
- `app/models.py` — SQLAlchemy-модели и связи;
- `app/tasks/` — Celery и обработка видео;
- `app/services/storage.py` — S3/RustFS;
- `alembic/` — миграции схемы;
- `frontend/` — адаптивный HTML/CSS/JavaScript интерфейс;
- `media/` — демонстрационные медиафайлы;
- `tests/` — автоматические тесты API и безопасности;
- `docs/` — архитектура, БД, API, безопасность и тест-план;
- `AGENTS.md`, `.cursor/`, `.claude/` — правила работы ИИ-инструментов;
- `ai_artifacts/` — место для оригинальных экспортов диалогов.

## Проверки

```bash
pytest -q
python -m compileall -q app
```

Автотесты используют SQLite и подменяют S3-хранилище/Celery, чтобы проверять API без запущенной инфраструктуры. Для end-to-end проверки в Docker используйте сценарий из `docs/TEST_PLAN.md`.

## Важные эксплуатационные замечания

- По умолчанию `COOKIE_SECURE=false`, что подходит для локального HTTP. Для HTTPS-продакшена установите `COOKIE_SECURE=true` и разместите приложение за TLS reverse proxy.
- Измените `APP_SECRET_KEY`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и пароли БД перед публичным развёртыванием; ограничьте доступ к консоли RustFS и не публикуйте порты 9000 и 9001 в интернет.
- `MAX_UPLOAD_BYTES` по умолчанию равен 2 GiB. Настройте лимит также на reverse proxy и диске временных файлов.
- Для настоящей эксплуатации дополнительно нужны антивирусная проверка, лимиты частоты запросов, аудит действий модераторов, резервное копирование, мониторинг очереди, CDN и HLS/DASH для адаптивного стриминга. Они не заявляются как реализованные в этой версии.

## Материалы ИИ и Git

В репозитории есть инструкции для ИИ-агентов и вспомогательные промпты. Однако требование задания о диалогах в исходном формате означает, что в архив нужно отдельно добавить **реальные** экспорты только тех сессий, которыми вы пользовались: Cursor export, `~/.claude/projects/<project>/*.jsonl`, либо отфильтрованные данные экспорта ChatGPT. В `ai_artifacts/README.md` описано, куда их положить. Синтетические стенограммы вместо исходных файлов не создавались.

В проект включён Git-репозиторий с последовательной историей изменений. Коммиты отражают этапы сборки реализации, а не экспорт истории вашей локальной работы в IDE.
