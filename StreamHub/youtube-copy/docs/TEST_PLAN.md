# Тест-план и ручная проверка

## Автоматические тесты

```bash
pytest -q
```

Тесты покрывают хеширование паролей и JWT, регистрацию/вход/выход, дублирование аккаунтов, приватный доступ и отзыв grant, лайки/комментарии, очередь загрузки и роль модератора. S3 и Celery подменяются в upload-тесте, чтобы тесты были детерминированными и не зависели от Docker.

## End-to-end сценарий после `./deploy.sh`

1. Открыть `http://localhost:8000`, убедиться, что на главной есть демо-видео.
2. Войти как `demo@streamhub.local` / `DemoPass123!`, открыть ролик, поставить лайк и оставить комментарий.
3. Выйти и зарегистрировать нового пользователя.
4. Открыть «Загрузить видео», выбрать MP4, заполнить название/описание, выбрать «Открытое» и отправить. Проверить прогресс; через несколько секунд видео должно появиться на канале.
5. Открыть загруженный ролик и проверить воспроизведение, перемотку, счётчик просмотров и превью.
6. Загрузить второе видео как «Приватное». Владелец должен открыть его; другой аккаунт по прямой ссылке получает 404.
7. От имени владельца выдать доступ второму аккаунту по email. Второй аккаунт после этого может открыть видео. Отозвать grant и проверить, что доступ снова закрыт.
8. С аккаунта другого пользователя пожаловаться на публичное видео. Войти как `moderator@streamhub.local` / `ModerPass123!`, открыть `/studio/moderation`, обработать жалобу и скрыть ролик. Он должен исчезнуть из ленты и стать недоступным обычному зрителю.
9. Проверить плейлист канала, поиск, подписку и документацию `/docs`.

## Что смотреть в логах

```bash
docker compose logs -f api worker
```

При успешной обработке worker должен записать `status=ready`, `processed_key`, `thumbnail_key` и `duration`. При ошибке `status=failed` и диагностическое сообщение появится в `processing_error`.
