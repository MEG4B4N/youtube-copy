# Архитектура StreamHub

## Компоненты и границы ответственности

| Компонент | Ответственность | Хранимые данные |
|---|---|---|
| FastAPI | Авторизация, API, политика доступа, раздача файлов, интерфейс | Нет постоянного хранения медиа |
| PostgreSQL | Пользователи, роли, метаданные, отношения и статусы | Только структурированные данные и ключи объектов |
| RustFS (S3-compatible) | Хранение загруженных оригиналов и производных файлов | MP4, JPEG и метаданные объектов |
| Redis | Брокер Celery и backend результатов | Короткоживущие сообщения задач |
| Celery worker | Проверка контейнера, перекодирование, превью и обновление статусов | Временные файлы в рабочем каталоге |
| FFmpeg / ffprobe | Проверка длительности и создание производного MP4 / thumbnail | Не хранит данные самостоятельно |

## Жизненный цикл видео

1. Автор проходит аутентификацию и отправляет multipart-запрос с файлом и метаданными.
2. API проверяет расширение и фактический размер перед записью в объектное хранилище RustFS. Исходный файл получает уникальный ключ `originals/<user>/<uuid>.<ext>`.
3. В PostgreSQL создаётся `videos` со статусом `processing`; в Redis публикуется задача `process_video(video_id)`.
4. Worker скачивает оригинал во временный каталог, проверяет duration через ffprobe, перекодирует MP4 H.264/AAC, создаёт JPEG thumbnail и сохраняет производные объекты.
5. Worker записывает ключи производных объектов, длительность и статус `ready`. При ошибке статус становится `failed`, диагностическое сообщение сохраняется в `processing_error`.
6. Клиент получает метаданные и проигрывает `/api/videos/{id}/stream`. FastAPI проверяет ACL и передаёт диапазон байтов в RustFS; само объектное хранилище не публикуется браузеру.

## Состояния

`processing → ready | failed`. Видео не попадает в общую ленту и поиск, пока статус не `ready`. Скрытое видео не выдаётся в публичных endpoints. Изменение роли/доступа выполняется на сервере, а не доверяется состоянию UI.

## Масштабирование

API можно масштабировать горизонтально за reverse proxy. Worker масштабируется независимо количеством Celery-процессов. Для крупной нагрузки следующий шаг — HLS/DASH-транскодирование нескольких профилей, CDN и отдельный media gateway с подписанными URL. Текущая версия отдаёт MP4 с byte-range через API; это проще и безопаснее для демонстрации, но пропускает медиатрафик через FastAPI.
