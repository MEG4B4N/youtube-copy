# Безопасность: реализованные меры и границы

## Реализовано

- Пароли хешируются Argon2 через `pwdlib`; исходные пароли не сохраняются.
- JWT подписывается HS256 с истечением срока действия. Для браузера cookie `HttpOnly`, `SameSite=Lax`; флаг `Secure` включается переменной `COOKIE_SECURE`.
- Cookie-authenticated mutating requests отклоняют несовпадающий `Origin`/`Host` (при наличии Origin). API и фронтенд обслуживаются с одного origin; CORS не открыт.
- Авторизация и проверка ролей выполняются в зависимостях FastAPI на сервере.
- Приватный доступ проверяется перед чтением метаданных, потока и превью. Владелец может выдать или отозвать grant зарегистрированному пользователю по email.
- Поиск, главная лента и публичные страницы каналов/плейлистов не раскрывают приватные видео.
- Раздача объекта проходит через API, поэтому ключи и endpoint объектного хранилища не раскрываются клиенту.
- Загрузка ограничена набором расширений и размером `MAX_UPLOAD_BYTES`; API проверяет базовую сигнатуру MP4/MOV или EBML для MKV/WEBM, а worker выполняет проверку контейнера через ffprobe. Имя объекта формирует сервер, имя файла пользователя не используется как object key.
- Ошибки API возвращаются в контролируемом формате; S3 credentials и пароли не выводятся в интерфейс.
- Действия скрытия/восстановления видео и разрешение жалоб доступны только moderator/admin.

## Ограничения и следующие меры для production

Эта версия является тестовой реализацией, не аудитом безопасности. Перед публичной эксплуатацией следует добавить антивирусную/контентную проверку, rate limiting и защиту от brute force, управление сессиями/отзыв JWT, полноценную CSRF-модель с проверкой Origin на reverse proxy, CSP и другие security headers, аудит действий модераторов, политику хранения/удаления данных, резервное копирование и централизованные логи. Также нужен HTTPS reverse proxy; включить `COOKIE_SECURE=true`; закрыть прямой внешний доступ к консоли RustFS и внутренним сервисам. Защитить FFmpeg sandbox/лимитами ресурсов от специально подготовленных файлов.

## Приватность

Приватное видео выдаётся владельцу или пользователям из `video_access`. Администратор и модератор не получают автоматический доступ к приватному контенту через обычные video endpoints. Это минимизирует привилегированный доступ; отдельный процесс legal/safety review для жалоб не реализован.
